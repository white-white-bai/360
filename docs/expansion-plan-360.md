# 拓展计划书:从“讲清一个技术点”到“三百六十行都能教”

状态:阶段 0 与阶段 1（行业骨架）已落地，见 ADR 0012；其余阶段待推进
依据:2026-09-30 对仓库的盘点（`CONTEXT.md`、ADR 0001–0011、`platform/src`、`domains/`、`library/`）

## 0. 已拍板的六个决定（2026-09-30，落成 ADR 0012）

1. **分类骨架**：以《中华人民共和国职业分类大典（2022 年版）》八大类为骨架；「三百六十行」等民间称呼只作别名，不作分类。
2. **C 层（具身技能）**：接受"只教认知层并明说边界"——边界写进数据（`boundary`），校验器可查。
3. **D 层（高风险）**：在没有两名独立审核人之前完全关闭——包括直接课堂。这是硬拒绝，不是免责声明；两道门（建课路径与直接课堂）在调用模型之前拒绝高风险主题。
4. **审核者**：来自行业从业者，平台无法代劳；落地前以 `profession.high-risk-open` 规则锁死高风险行业。
5. **直接课堂**：保留为长尾探索入口，但受同一道门约束（ADR 0011 不变）。
6. **ADR 0002 修订**：目录分两层显示——行业目录（按状态：可学/待建/未开放）在上，教材目录（已签 Domain）在下；行业目录的长度同样是诚实陈述。

已落地（本次）：`professions/professions.md`（8 大类 + 10 个试点行业）、加载器与状态计算、校验器新规则（`profession.*`、`domain.overlap`、`domain.unlisted`、`corpus.source-unusable`、`corpus.source-redirected`）、入口页面行业目录、抓取器拒绝错误页、两个已签 Domain 的垃圾来源清理（屏蔽页不支撑任何语料段落）、CLAUDE.md 与 CONTEXT.md 更新、7 个新测试。

待办（阶段 1 剩余）：把 1639 个职业按试点经验逐步补进 `professions.md`；为 B/C 层行业建立"不替代实操"的标准表述；高风险行业的两个独立审核人机制（签字字段扩展）。

## 1. 目标与诚实边界

**目标**:学习者说出任何一个行业/岗位,平台能带他从“外行”走到“能上岗的知识层”,并且平台自己清楚地知道、并明说哪些东西教不了。

**不承诺的部分**:“样样精通”不作为产品承诺。`CONTEXT.md` 已经有一条原则:Catalogue 的长度是对“平台真能教什么”的诚实陈述。拓展后这条原则要扩成:**每个行业都要标明平台能教到哪一层、教不了什么。**

---

## 2. 现状:离目标有多远

已经有的(可复用的骨架):

| 能力 | 现状 |
|---|---|
| 教学内核 | 讲解者 + 质疑者、Probe/Understanding Check、错误概念驱动的复教,已跑通 |
| 内容可信 | 语料必须溯源;逐字引文证明(`build/quotes.ts`);独立校验者;签字门 |
| 按需建域 | 输入题目 → 规划 → 抓取 → 选段 → 证明 → 撰写 → 校验 → 页面签字 |
| 直接课堂 | 任意题目、无语料、明示“未校验”,靠两段提示词驱动 |
| 实验方法 | 基线对比消融,不增益的部件删除(ADR 0001) |

缺的(按对“360 行”的阻碍程度排序):

| # | 缺口 | 证据 | 严重度 |
|---|---|---|---|
| G1 | **没有行业结构**:无行业分类、无“行业→能力→Domain”层级、无待建队列 | 全仓库检索不到任何分类;Catalogue 只是 `domains/` 目录列表;ADR 0002/规划提示词写着“行业不是 Domain” | 高 |
| G2 | **内容全是软件类**:7 个 Domain 全是技术文本主题 | `domains/` 清单 | 高 |
| G3 | **来源只能读文本**:抓取器拒绝 PDF/图片/视频;单文档 10k 字、合计 40k 字截断 | `build/fetch.ts`、`build-domain.ts` | 高。国标、行业规范、技能标准大多是 PDF |
| G4 | **来源靠模型凭记忆给 URL**:规划器直接产出网址,没有检索环节 | 已出现两处 `app-unavailable-in-region` 垃圾来源被签字放行 | 高 |
| G5 | **黑板词表偏抽象**:文本、形状、坐标轴、区段、表格、指向/高亮/擦除,加 `rich`(mermaid/excalidraw/svg) | `events/types.ts` | 中。无图片、公式、代码、步骤序列 |
| G6 | **检查题只能“说出来”**:客观判分靠文本预期答案;未覆盖计算、情景判断、识图、操作 | `checks/grade.ts`、`checks.md` 结构 | 高。操作类行业没法验 |
| G7 | **没有学习者模型与课程**:一次会话 = 一个 Assertion List;无先修关系、无水平诊断、无跨会话档案、无复习计划 | `session/store.ts`、`resume.ts` 只做续课与次日回访 | 高。“精通”靠的是路径,不是单课 |
| G8 | **签字不可扩展**:一个 Owner、手工逐个签 | ADR 0006/0010 | 高。高风险行业不能靠一个人签 |
| G9 | **规模化运维缺失**:Domain 重叠无检测(已有 4 个近重复)、无新鲜度/重抓机制、无成本预算、无质量看板 | ADR 0010 提到“清扫”但未做 | 中 |
| G10 | **Library 太薄**:2 个 Persona、2 个 Style,且例子绑定时区/RFC | `library/` | 中 |
| G11 | **入口在规模下会失效**:Catalogue 用完整可见的单选列表,几百项时不可用 | `taste` 已表明“目录不能藏在下拉框里” | 中 |
| G12 | **工程底座偏原型**:单文件 UI(约 1000 行)、单文件 HTTP 服务(约 970 行)、按会话存 JSON、无账号;`CLAUDE.md` 已过时 | 盘点 | 低到中(先不动,到多用户再动) |

**总体判断**:内核(可信讲解 + 验证)方向对、质量高,但现在是“一个窄领域的深井”。要走向 360 行,主要缺 **结构(G1)、来源(G3/G4)、检验方式(G6)、学习路径(G7)、审核产能(G8)** 五件事,而不是再多写几个 Domain。

## 3. 核心设计决定:行业不是 Domain,但要能到达 Domain

引入三层结构(需在 `CONTEXT.md` 新增术语并写 ADR):

- **Profession(行业)**:学习者的入口单位,对应一行。只是目录节点,不直接授课。
- **Competency(能力单元)**:一个行业内“必须知道并能应用”的一块,按先修关系连成图。粒度以“一节课讲得完”为界。
- **Domain**:保持现有含义,一个 Domain 服务一个或多个 Competency,仍需语料、错误概念、术语表。

规模估算:360 行 × 每行约 10–20 个能力单元,是几千个 Domain 级别。**不可能逐个手签,也不该逐个预建。** 所以策略是:**先建骨架,按需加深,按风险分级审核**,不追求全量预建。

### 3.1 教得了多少:可教性分层(每个 Profession 必须标注)

| 层 | 含义 | 例子 | 平台做法 |
|---|---|---|---|
| A 文本可验证型 | 知识可由公开文本溯源,检查可客观判分 | 软件、会计、税务、法规类 | 走完整的有据课堂 |
| B 标准+图示型 | 有公开标准与规程,需要图示,判分半结构化 | 电工、焊接、食品安全、护理规程 | 有据课堂 + 图示 + 情景题;标明“不替代实操” |
| C 具身技能型 | 核心在手上功夫,文本只能覆盖认知部分 | 理发、木工、厨艺、驾驶 | 只教认知层(原理、安全、常见错误),明示边界,建议实操路径 |
| D 高风险型 | 教错会造成人身/法律/财产后果 | 医疗、特种作业、法律、金融 | 在 A/B/C 之上叠加:强制专业审核、显著声明、拒答边界 |

分层和风险是两个维度,写进 Domain 元数据(`tier`、`risk`),校验器据此收紧规则。

### 3.2 直接课堂的位置

直接课堂(ADR 0011)是覆盖长尾的最快手段,但它没有校验。建议定位为:**探索入口,不是学习入口的终点。**
- 高风险(D 层)行业中,直接课堂只能给出“未校验”声明,且默认拒绝给出操作性建议。
- 学习者在直接课堂里反复问到某个主题,把它作为 Domain 建设队列的输入(ADR 0008 已埋这个点,“未实现”)。

## 4. 分阶段计划

每个阶段给出“做什么 / 退出条件”。不设时间,按退出条件推进;阶段之间允许并行,但退出条件不满足不得宣称覆盖。

### 阶段 0:整顿地基(先做,成本低)

- 清理 4 个近重复 Domain(`agent-dev-essentials`、`llm-agent-tool-calling`、`agent-app-dev-core`、`agent-app-development`),按 ADR 0010 “签字时清扫”执行,保留一个或合并。
- 校验器新增:来源文本为空/地域屏蔽页/过短即报错(修 G4 的一半);Domain 之间来源重叠率超阈值报警(G9)。
- 更新 `CLAUDE.md`(已过时:仍写“没有 git 仓库、不是软件项目”)。
- `CONTEXT.md` 增补术语:Profession、Competency、Tier、Risk、Reviewer。

**退出条件**:`npm run validate` 对现有全部 Domain 通过新规则;Domain 间无未解释的重叠。

### 阶段 1:行业骨架(G1、G11)

- 选定分类骨架。候选:《中华人民共和国职业分类大典》(国家发布,分类层级清晰),再用“三百六十行”式的民间行业作为入口别名。**需核实最新版本与可引用条款**后再定。
- 产出 `professions/` 数据(只有骨架):行业 id、名称、上级、别名、可教性分层、风险等级、状态(未建/草稿/可学)。
- 入口改成两级浏览 + 搜索:第一级“行业大类”完整可见(沿用“目录必须完整可见”的偏好),第二级“行业”,搜索框仍可输入任意题目(保持“学什么是输入框”的既有决定)。
- 每个行业显示状态:平台能教到哪一层、哪些已有 Domain、哪些等待建设。

**退出条件**:全部目标行业在目录中有节点与分层标注;学习者能从页面点进任一行业并看到诚实的覆盖说明;没有 Domain 的行业不假装能教。

### 阶段 2:来源与建域能力(G3、G4)

- 抓取器支持 PDF(以及扩展的中文来源);引文证明沿用“抽取文本上逐字定位”的原则,保证检查和语料用同一种表示。
- 规划器加检索环节:来源由搜索结果 + 权威性打分给出,而不是模型凭记忆写 URL;失败来源在页面上列出原因(沿用“失败要能看见”的偏好)。
- 来源分级:标准/法规/官方文档 > 教材/行业协会 > 其他;D 层 Domain 只允许前两级。
- 版权:保留“来源全文不入库、只入 gitignored 的 sources/,语料只放有限引文”的做法,补写 ADR 说明理由。
- 截断策略:目前单文档 10k 字、总 40k 字;需按文档结构分段选段,而不是截头部。

**退出条件**:对阶段 1 选出的试点行业,能从 PDF 标准中建出通过校验的草稿;垃圾来源在建域阶段就被拦下,而不是等签字。

### 阶段 3:检验方式与黑板扩展(G5、G6)

- 新增检查题类型,且每种都要有独立于讲解者的客观判分:
  - 计算题(数值 + 单位 + 容差)
  - 情景判断/排序(正确步骤序列)
  - 识图/找错(依赖黑板图片)
  - 对 B/C 层:“你会怎么做、为什么”的开放题,由校验者按错误概念目录判分
- 黑板词表扩展需要 ADR:候选新增 `image`(带出处)、`formula`、`steps`(步骤序列)、`code`。原则不变:词表仍是封闭的,新增种类也要在 `assertBlackboardEvent` 里被严格校验。
- 每加一种,先在基线对比里证明有增益,否则不合并(ADR 0001)。

**退出条件**:A、B 两层各有至少一个 Domain 用新检查题完整跑通,并在实验里得到与基线的对比数据。

### 阶段 4:学习者模型与路径(G7、G10)

- Competency 先修图:每个 Competency 声明前置。
- 入学诊断:用已有的 Understanding Check 机制做“摸底”,决定起点,而不是新建一套测评系统(保持最轻机制)。
- 跨会话学习者档案:已掌握/未掌握的错误概念、复习到期项(在现有“次日回访”上扩展为间隔复习)。
- 路径页:学习者看到“我在这个行业的哪一步”,能一键继续。
- Library 扩充 Persona/Style,并去掉与时区绑定的示例;新增按年龄/基础的 Style 选择,仍由学习者在入口选(ADR 0007)。

**退出条件**:一个试点行业能被学习者连续学完多个 Competency,系统据档案给出下一步并触发到期复习;有数据显示复习提升了保持率。

### 阶段 5:审核产能与规模运维(G8、G9)

- 审核角色:Owner(对一个 Domain 负责)与 Reviewer(专业审核)分开;签字记录写明身份、资质、范围、日期。
- 风险分级审核:A 层一位审核;B 层需行业相关审核;D 层需两位独立审核且不得由建域者自己签(延续“没有行为者验证自己的输出”的原则,ADR 0004)。
- 页面上的审核台扩展:批量队列、按风险排序、差异视图(来源重抓后的变化)。
- 新鲜度:定期重抓来源,sha256 变化时把 Domain 标为“待复核”,学习者端显示。
- 成本与看板:每个 Domain 的建域成本、被学次数、检查通过率、错误概念命中分布。
- 待建队列:直接课堂/搜索未命中的题目汇总成待建清单,由 Owner 决定建什么。

**退出条件**:审核和重抓流程在试点行业里跑通一个完整周期;任何一个 Domain 都能回答“谁审的、什么时候、依据什么、是否过期”。

### 阶段 6:证据与放量

- 每个可教性层单独做一次基线对比,不再拿时区的结论代表所有领域。
- 按层设定放量门槛:A 层通过后才批量扩;C 层只有认知层通过检验才开放;D 层没有审核资源就保持关闭。
- 覆盖率对外表述只用“已开放行业数/各层数量”,不用“已覆盖 360 行”。

## 5. 试点建议

先挑 10 个行业,覆盖 A–D 四层,目的是暴露缺口而不是凑数:

| 层 | 试点候选 |
|---|---|
| A | 软件开发(已有基础)、会计 |
| B | 电工、食品安全/餐饮 |
| C | 理发、木工 |
| D | 护理、法律助理 |
| 混合 | 教师、汽修 |

这里的选择需要你决定,我倾向用它们是因为这些行业在来源形态(PDF 标准、图示、实操)上差异最大。

## 6. 已决(见上文第 0 节与 ADR 0012)

六个问题均已按 ADR 0012 拍板:官方大典作骨架、三百六十行作别名;C 层教认知层并写明边界;D 层在两名独立审核人之前完全关闭(含直接课堂);审核者来自行业从业者;直接课堂保留为受同一道门约束的探索入口;目录分行业目录与教材目录两层显示。

## 7. 风险

- **来源质量**:签字放行了空来源,说明人工把关不可靠,要让校验器兜底。
- **审核瓶颈**:产能上限是审核者数量,而不是模型调用。
- **误导风险**:D 层教错的后果重,宁可不开放。
- **范围失控**:几千个 Domain 的目标会拖垮验证质量;必须坚持“按需加深”。
- **与既有决定冲突**:直接课堂和按需建域已经放宽了 ADR 0002;继续放宽前要明确记录理由。
